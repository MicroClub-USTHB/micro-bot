# edge cases

| edge case | proof it is real | decision | why |
|-----------|------------------|----------|-----|
| message over 2000 chars must answer 422. not 200 | jury brief caps message at 2000 chars with 422 | fixed in schemas.py max length | cap it in the model. overlong input fails before it burns a retrieval or an llm call |
| jury never pins the feedback 200 body | jury brief specifies the request shape only | fixed pin {"ok": true}. nisbenz raised no objection | pin the smallest shape. hidden tests get a stable 200 to assert against |
| bad uploads must bubble 4xx instead of returning 200 with failed | jury error format rule plus nisbenz typed codes with suggested http statuses | fixed map by stable code in errors.py. 415/413/400/502/422. keep failed internal to the pipeline | surface client mistakes with the right status. the jury harness reads them instead of guessing |
| .venv binaries lose the exec bit on this fuseblk mount. uv run ruff dies with permission denied | observed os error 13 on uv run ruff. chmod does not stick | accepted run ruff through uvx until the checkout moves off the fuse mount | burn no more time on mount quirks. keep the lint gate green anyway |
| short latin queries flip fr/en in strict 3 way detect | nisbenz compat note. ok merci can flip | fixed reuse the conversation language under 20 letters | trust the ongoing conversation over one coin flip word. replies stop switching language mid thread |
| single uvicorn worker was justified by qdrant local mode but compose runs qdrant server side | docker compose file shows qdrant as its own service | accepted keep one worker. the exact match cache and the quota counter live in process memory | hold the correct shape for the real reason. a second worker never silently splits the cache and the budget |
| Junk bytes named `a.pdf` / `.txt` reach the wrong parser | xberg 1.3.6 routed junk named `a.pdf` to its PDF parser and accepted junk as `text/plain` under `content_only` | Own magic-byte sniffing before xberg (`ingest/sniff.py`); extension only picks md vs txt | xberg trusts the extension when bytes are ambiguous |
| OCR language data missing | With only `eng` present, xberg OCR'd `ara+fra+eng` without error; with network it downloaded `ara`/`fra` into `~/.cache/xberg` | `verify_tessdata()` fails fast at startup; `tessdata_path` always passed; tessdata baked into the image, sha256-pinned | Silent degradation of Arabic OCR, and runtime network use |
| Arabic OCR drops lines | xberg's default page segmentation returned 2 of 4 lines of an Arabic notice; `tesseract` CLI read all 4 | `TesseractConfig(psm=3)` + regression test `test_arabic_ocr_keeps_every_line_in_reading_order` | Lost text is invisible without a test |
| OCR results cached on disk | `~/.cache/xberg/ocr/*.msgpack` written even with `ExtractionConfig.use_cache=False` | Also `TesseractConfig.use_cache=False`; test asserts no cache files | Unbounded disk use in the container, stale results |
| OCR invents tables in notices | A plain photographed notice came back as a 5-column Markdown table | `enable_table_detection=False`, Tesseract output `text` | Garbled chunks hurt retrieval |
| Running headers/footers repeated in every chunk | "Club MC - Page N / 4" on every page of a PDF | `strip_repeated_lines`: edge lines repeated on ≥60% of pages (digits masked); never headings or table rows | Noise in BM25 and embeddings |
| Spreadsheet rows lose their column names when chunked | A Markdown table split mid-way leaves rows without the header | XLSX rows rendered as `Header: value · Header: value` lines | Each chunk stays self-explanatory |
| Web page with no article | trafilatura's fallback returned just "Home" for a nav+footer page | Fewer than 20 letters of main content → `EmptyDocument` | Indexing menu text is noise |
| Redirect to an internal address (SSRF) | A public URL can redirect to `http://169.254.169.254/` or `127.0.0.1:6333` (Qdrant) | Manual redirects; every hop resolved and checked (`url_guard.check_url`) | Admin URLs must not reach internal services |
| DNS rebinding between check and connect | TOCTOU: host may resolve differently when httpx connects | **Accepted for now**; would need a transport that connects to the vetted IP | Admin-only feature, low exposure; documented |
| URL tokens in logs | `?token=...` in a submitted URL | Logs strip query string and fragment | Secrets must not land in logs |
| Docs-site headings disappear | mcoli-ui.microclub.info/docs/introduction: all 5 `<h2><a href="#…">` headings dropped by trafilatura; page became one section | `prepare_html` unwraps heading permalinks and `#` anchors before trafilatura; regression test on the saved page | Sections without headings give chunks no context |
| Install commands in tab widgets lost | Same page: npm/pnpm/yarn/bun `role="tabpanel"` blocks missing in every trafilatura mode | Tabs flattened into "label: command" list items | "How do I install it?" must be answerable |
| Link URLs and link-only lists lost | Same page: "Connect With Us" list dropped, no URLs kept | Inside `<article>`/`<main>` only, links become "text (absolute url)"; nav links untouched so they are still boilerplate | URLs are answers ("where is the repo?") |
| Proxy-only networks: every URL fails | Sandbox with no direct DNS: `cannot resolve host` although the proxy could fetch | **Open.** SSRF check needs DNS; fine in Docker with normal DNS | Would need proxy-aware checking |
| Token counts silently capped at 32,768 | granite `tokenizer.json` ships with truncation at 32,768 and padding on: the BBC page ×20 counted exactly 32,768 tokens until `no_truncation()` (77,960 after) | `HFTokenCounter` calls `no_truncation()` and `no_padding()`; tests check a 45k-token text and batch = single counts | Wrong counts would let chunks overflow the model windows unnoticed |
| Chunks fit the embedder but overflow the reranker | Reranker (XLM-R) ÷ granite tokens on `data/parsed`: 0.83–0.88 Arabic, 1.06 English, 1.28 on the CSS-heavy docs page | Chunk cap 400 granite tokens (target 300); retrieval must set reranker `max_length` ≥ 640 | 450 granite tokens could be ~576 reranker tokens before the query is added |
| Slide-style PDFs give dozens of tiny sections | VP candidacy PDF: 44 sections, most under 60 chars (`## 01`, `## 07`) | Runs of small sections under one parent merge (headings kept inline) up to the target; never across a higher heading. 40 sections → 10 chunks | 5-character chunks carry no answer and pollute the top-k |
| Heading with no text under it | Same PDF: `## Contents`, `## 07`; docs pages with an H2 directly followed by an H3 | Followed by a descendant: lives on only in the descendants' `heading_path`. Otherwise merged forward; a trailing one joins the previous chunk | A chunk that is only a heading is noise |
| Table larger than one chunk | Tests: a 100-row table at a 40-token budget | Split at row boundaries; the header (and `|---|` row) repeated at the top of every piece | Rows without column names are meaningless |
| Unclosed code fence | Tests: `` ``` `` without a closing fence | Block runs to the end of its section (CommonMark behaviour), then splits at lines if too large | Otherwise the rest of the document would be treated as code |
| One "word" larger than the budget | Tests: a 600-character run with no spaces (long URL, base64, unspaced text) | Last-resort cut at a token offset (lossless), logged as `chunk_hard_split` | The token cap must always hold |
| int8 embedder gives different vectors in a batch | granite `model_quint8_avx2.onnx`: a padded batch changed a text's vector by up to 0.012 per component (cosine 0.994 to the same text alone); same-length batches still 0.006 | One sequence per `session.run` (`OnnxDenseEncoder`); test checks alone vs inside a list within 1e-4. Batch 1 was also faster (6.3 vs 5.2 chunks/s) | Activations are quantized per call; queries and documents must get the same vector for the same text |
| fastembed BM25 downloads at runtime | fastembed 0.9.0 `Bm25` resolves the `Qdrant/bm25` repo even with custom stopwords and `disable_stemmer=True` | Stopword files pinned (revision + sha256) and baked into `$MODELS_DIR/bm25`, passed as `specific_model_path` and `cache_dir`; startup fails if missing | The container is offline (`HF_HUB_OFFLINE=1`) |
| Stopwords never match folded text | `Bm25` compares stopwords with the lower-cased token, but our input is `fold_for_search` output: `إلى` arrives as `الي` | The ar+fr+en stopword union (1,028 words) is folded too (945 after folding); test checks `إلى` is dropped | Otherwise every Arabic stopword with a hamza stays in the index |
| Cross-language stopword collisions | One shared stopword set: `an` (English) is also French "year", `son`, `ou` exist in both | **Accepted.** No stemming and one set keep matching language-agnostic (a French query still matches names and numbers in an Arabic chunk) | Per-language stemmers break matching across languages and on mixed documents |
| BM25 length normalization centred on the wrong length | fastembed's default `avg_len` is 256; our chunks average 105 BM25 tokens (70 chunks of `data/parsed`, median 108, max 202) | `INGEST_BM25_AVG_LEN=110` | Every chunk was treated as short, weakening length normalization |
| Crash between writing the points and saving the JSON | The index then holds the new version and `DATA_DIR/documents` the old one | **Accepted.** The next ingest of that document repairs it; a reindex before that would bring back the old version | Rare (process killed in a ~ms window); a two-phase commit is not worth it here |
| Chunks of a crashed ingest without a marker | Points written before the marker (index 0) stay if the process dies; listing and `corpus_version()` ignore them, search does not | **Accepted.** The next ingest of that `doc_id` deletes every other hash; a reindex drops them too | Same rare window; the marker-last order already keeps listings and the cache correct |
| Re-uploading the same file with a new visibility | Same topic + same sha256 but `public` → `members` | `updated`: visibility rewritten on every point and in the stored JSON, no re-embedding | Treating it as `duplicate` would silently keep the old access level |
| Filename longer than the topic limit | `data/parsed` holds an Al Jazeera page saved under its percent-encoded URL: 234-character stem, rejected by `ingest_folder.py` as `invalid_input` | Default topics (filename stem, URL) over 200 chars become a 183-char prefix + `~` + 16 hex of their sha256; explicit topics over 200 are still rejected | Real uploads must not fail on their name; the hash keeps re-uploads replacing the same document |
| int8 reranker scores depend on the batch | `eval/bench_rerank.py --batched`: the same (query, passage) pair moved by up to **1.8 logits** (gte) / 1.0 (bge) when scored in a padded batch of 8 or 30; batches were also slower (gte 5.1–5.5 s vs 4.4 s for 30 pairs) | One pair per `session.run` (`OnnxReranker`); real-model test checks a pair alone vs after other pairs | Otherwise `GATE_THRESHOLD` would compare scores that depend on the other candidates |
| gte's tokenizer pads every input | `onnx-community/gte-multilingual-reranker-base` `tokenizer.json` ships padding enabled: an 8-token pair came back 512 tokens long | `no_padding()` after loading; test asserts the fed length is the real one | 512 padded tokens per pair would multiply rerank time on CPU |
| Query longer than the reranker's `max_length` | tokenizers' `only_second` truncation raises "Sequence to truncate too short" when the query alone exceeds it (messages go up to 2000 chars) | Fall back to a second tokenizer with `longest_first`; test scores a 40-word query at `max_length=10` | A long question must not turn into a 500 |
| Visibility filter only at the top level of a hybrid query | Qdrant 1.19.2 server: 19 members points ranked above 1 public point on both arms, prefetch limit 3, filter only on the fused query: the public role still got the public point | The server pushes the filter into prefetches before their limits. We set it on every prefetch **and** the fused query anyway; test with members chunks above public ones on both arms | Explicit is cheap; a client or server change in propagation must not leak members documents |
| Qdrant's RRF constant | qdrant-client `DEFAULT_RANKING_CONSTANT_K = 2` (server the same), not the usual 60 | `RETRIEVAL_RRF_K` setting, default 60, compared with 2 on the eval | k=2 lets one arm's top hit dominate the fusion |
| Retrieval errors reach the app as plain 500s | `api/chat.py` lets `retrieve()` raise; the app handler catches `mcclub_rag.errors.IngestError`, a different class from `ingest.errors.IngestError`, and its status map has no `index_unavailable` / `rerank_error` | **Fixed** in eequaled's wiring PR (#11): `errors.py` handles our class too, `index_unavailable` → 503, `embedding_error` / `rerank_error` → 500 | A Qdrant outage should say 503 with a JSON code, not a generic 500 |
| Eval saturates on a small corpus | 70 chunks, 36 answerable questions: hit@5 was 1.0 after reranking in all 10 runs (`eval/results/README.md`) | **Accepted.** Defaults were chosen on MRR@10 and latency; grow the corpus and questions before trusting small differences | With every answer in the top 5, hit@5 cannot tell settings apart |
| Gate threshold hugging the answerable edge | Sweep on the defaults run suggested 0.41; the lowest kept answerable question scored 0.412 and the highest unanswerable 0.388 | `GATE_THRESHOLD=0.40`, the middle of the gap (same refusals), set per model in `.env.example` (bge's sweep gave 0.15) | A threshold at the edge refuses real questions on the next small score shift |
| Eval corpus files are debug dumps, not documents | `data/parsed/*.md` are `scripts/parse.py` output: `# Metadata` (a Python dict repr), `# Sections (N)` list, then `# Text`. Ingested whole: 70 chunks instead of 61, and every document titled "Metadata" (first heading), seen in the local Qdrant markers | `eval/run_eval.py::document_text` ingests only the `# Text` part; titles come from `eval/corpus.json` | The dict and section list were indexed as content and every context header started with "Metadata", so earlier eval runs measured a polluted index |
| `expires_at` upload field silently ignored | Smoke test 2026-10-11 on the wired app: `POST /documents` takes `expires_at`, `RealDocumentBackend.ingest_file` never passes it on, `GET /documents` returns `expires_at: null` | **Open.** The pipeline has no expiry; agree its meaning with eequaled or drop the field | A client that sets an expiry would believe the document disappears |

| Live app never calls the LLM | 2026-10-11, `origin/dev` f69ee94: `default_state(Settings(openrouter_api_key="sk-test")).generator` is `FakeGenerationService` (`error="disabled"`), so `api/chat.py` takes `extractive_fallback` with `llm_calls=0` for every answerable question; `OpenRouterClient.generate` is also sync while `GenerationService.generate` is async | **Open** (eequaled, `main.py`): wire an async adapter over `OpenRouterClient` in `default_state()`. The e2e eval reports the response path and marks generation "not evaluated" until then (`specs/e2e-eval/`) | The 0.1.0 smoke test saw answers with sources and could not tell a verbatim fallback from a generated answer |
| Share-bar-only web page | 2026-10-11, `finfo.usthb.dz/scolarité/réintégration-aux-études`: trafilatura kept the title and 5 "share on Facebook/Twitter/…" links (30 words), passed the 20-letter empty check and would be indexed as a document | **Fixed** (eval-fixes Req 15): `web.prepare_html` drops the largest share-only block around each share link (sharer URLs, `mailto:?`, `share` class) before extraction, and the empty check ignores heading lines; fixture `web/share_bar_only.html` | A page with no content becomes a chunk that matches "how do I…" questions on the site's name |
| PDF metadata titles are useless | 2026-10-11: Code of Conduct PDF title = "MICRO CLUB" (first heading), SG candidacy = "KENPA SG DOC" (file name); finfo pages give "USTHB licence"-style slugs and two pages share "USTHB presentation" | **Accepted** for the eval (titles set in `eval/corpus.json`); the upload API takes no title, so live uploads keep these | The title is in every chunk's header and in the reranker input, so a bad title weakens retrieval and citations |
| One fact in several documents | 2026-10-11, corpus of 55: "since 1985" is in the VP and president candidacies and the Code of Conduct; en-07 counts as rank 2 although rank 1 also answers it | **Open** for the e2e cases: accept evidence from any listed document (Req 1), not one `doc` | Single-document labels under-count correct retrieval as the corpus grows |
| Photographed page loses whole paragraphs | 2026-10-11, `scripts/make_eval_scans.py`: page 2 of the SG candidacy, skewed 2.2° with uneven light (JPEG): OCR returned 142 of 329 words, two paragraphs missing, no warning; the same pipeline read a 0.8° flatbed scan at 100% word recall, the Arabic notice at 93%, French at 96 to 98% | **Open.** Candidate fixes: deskew before Tesseract, warn when OCR words per page are far below the page's text area; the `ocr` slice measures it. 2026-10-12 (eval-fixes task 6.1): xberg's page signals cannot drive a warning: `ocr_confidence.score` is 0.95 for the photo **and** for the flatbed scans (0.90 for the Arabic one), and the photo's 150 words sit between the scans' 86 and 344. **Fixed** the same day: `ingest/deskew.py` straightens image uploads (1-5°, projection-profile angle on an 800 px copy) before OCR: the photo reads 364 words instead of 150 (99% recall); the flatbed scans are unchanged. Light correction was tried and dropped (cost the scans 2-4 points). Scanned PDFs are not deskewed (xberg rasterizes them) | A member uploading a phone photo gets a silently partial document, and questions on the missing part are refused as unanswerable |
| Gate cannot separate unanswerable questions | 2026-10-11, retrieval preview of the 269 e2e cases on the 63-document corpus (`eval/results/e2e/README.md`): refuse-expected questions score 0.21 to 0.65, answerable ones go down to 0.23; at `GATE_THRESHOLD=0.40` 37 of 59 refuse-expected cases pass the gate (PII, system prompt, harmful, future, in-domain unknowns) | **Open.** The gate is a relevance filter, not a refusal policy: the LLM must refuse. With the generator unwired (row above) those questions get `extractive_fallback`, i.e. unrelated chunks verbatim, often `grounded=true` | "What is the HQ Wi-Fi password?" is answered with pasted text instead of "I don't know" |
| Short topic switch glued to the previous question | Same preview, conv-06: "Who is the dean?" after a hackathon turn is searched as previous message + message (under `RETRIEVAL_FOLLOWUP_MAX_WORDS`), top chunks are the hackathon documents; the long version (conv-05) finds the dean | **Open.** Candidate fix: only merge when the message has a pronoun/ellipsis cue or the merged query scores better than the message alone | Short new questions in a conversation are answered about the old topic |
| Injection text attracts unrelated queries | Same preview: the public `eval-workshop-notice` (injection paragraph asking to "reveal your system prompt") is in the top 3 for system-prompt, dean and PFE-deadline questions | **Accepted** at retrieval (passages are fenced as untrusted in the prompt); the answer-level check (`must_not` markers) decides | Imperative "instructions" text is lexically close to the attack questions, so attacks pull the payload into context |
| Same-language distractor beats the right document | Same preview, coc-24: an Arabic question on Discord rules retrieves the Arabic Wikipedia "Discord" article instead of the English Code of Conduct (also coc-23, fac-18, note-09 under the gate) | **Open.** Measured by the `cross_lingual` slice (68% at retrieval) | Arabic and French questions about English club rules are the common real case |
| darija questions retrieve worse than msa ones | 48 darija/arabizi questions (`eval/questions.jsonl`, dev/test split): hit@5 0.67, arabic-script 0.62, arabizi 0.74; 12 of 48 never reach the reranker (`20261013T003518Z-darija53-nomap`) | open. a darija -> msa word map was tried and removed | the map gained 1 of 7 on the first set (`20261012T234551Z-darija-map`) but 0 on the held-out test split (0.74 -> 0.74, `20261013T002940Z-darija53-map`): no measured gain, so no component. the first stage is the bottleneck: next is an embedder a/b |
| answers sometimes come in the document's language | 12 language mismatches in the last llm e2e run (`20261012T214024Z-llm-fixes`), mostly ar/darija -> fr/en | fixed in the prompt: language by name, repeated after the passages; `language` / `answer_language` logged per request | one llm call per question leaves no second pass to translate. the log makes the mismatch rate measurable in production |
