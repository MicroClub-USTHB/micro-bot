# Edge cases

| Edge case | Proof it is real | Decision | Why |
|-----------|------------------|----------|-----|
| Junk bytes named `a.pdf` / `.txt` reach the wrong parser | xberg 1.3.6 routed junk named `a.pdf` to its PDF parser and accepted junk as `text/plain` under `content_only` | Own magic-byte sniffing before xberg (`ingest/sniff.py`); extension only picks md vs txt | xberg trusts the extension when bytes are ambiguous |
| OCR language data missing | With only `eng` present, xberg OCR'd `ara+fra+eng` without error; with network it downloaded `ara`/`fra` into `~/.cache/xberg` | `verify_tessdata()` fails fast at startup; `tessdata_path` always passed; tessdata baked into the image, sha256-pinned | Silent degradation of Arabic OCR, and runtime network use |
| Arabic OCR drops lines | xberg's default page segmentation returned 2 of 4 lines of an Arabic notice; `tesseract` CLI read all 4 | `TesseractConfig(psm=3)` + regression test `test_arabic_ocr_keeps_every_line_in_reading_order` | Lost text is invisible without a test |
| OCR results cached on disk | `~/.cache/xberg/ocr/*.msgpack` written even with `ExtractionConfig.use_cache=False` | Also `TesseractConfig.use_cache=False`; test asserts no cache files | Unbounded disk use in the container, stale results |
| OCR invents tables in notices | A plain photographed notice came back as a 5-column Markdown table | `enable_table_detection=False`, Tesseract output `text` | Garbled chunks hurt retrieval |
| Running headers/footers repeated in every chunk | "Club MC - Page N / 4" on every page of a PDF | `strip_repeated_lines`: edge lines repeated on ≥60% of pages (digits masked); never headings or table rows | Noise in BM25 and embeddings |
| Spreadsheet rows lose their column names when chunked | A Markdown table split mid-way leaves rows without the header | XLSX rows rendered as `Header: value · Header: value` lines | Each chunk stays self-explanatory |
| Web page with no article | trafilatura's fallback returned just "Home" for a nav+footer page | Fewer than 20 letters of main content → `EmptyDocument` | Indexing menu text is noise |
| Redirect to an internal address (SSRF) | A public URL can redirect to `http://169.254.169.254/` or `127.0.0.1:6333` (Qdrant) | Manual redirects; every hop resolved and checked (`url_guard.check_url`) | Admin URLs must not reach internal services |
| DNS rebinding between check and connect | TOCTOU: host may resolve differently when httpx connects | **Accepted for now**; would need a transport that connects to the vetted IP | Admin-only feature, low exposure; documented |
| URL tokens in logs | `?token=...` in a submitted URL | Logs strip query string and fragment | Secrets must not land in logs |
| Docs-site headings disappear | mcoli-ui.microclub.info/docs/introduction: all 5 `<h2><a href="#…">` headings dropped by trafilatura; page became one section | `prepare_html` unwraps heading permalinks and `#` anchors before trafilatura; regression test on the saved page | Sections without headings give chunks no context |
| Install commands in tab widgets lost | Same page: npm/pnpm/yarn/bun `role="tabpanel"` blocks missing in every trafilatura mode | Tabs flattened into "label: command" list items | "How do I install it?" must be answerable |
| Link URLs and link-only lists lost | Same page: "Connect With Us" list dropped, no URLs kept | Inside `<article>`/`<main>` only, links become "text (absolute url)"; nav links untouched so they are still boilerplate | URLs are answers ("where is the repo?") |
| Proxy-only networks: every URL fails | Sandbox with no direct DNS: `cannot resolve host` although the proxy could fetch | **Open.** SSRF check needs DNS; fine in Docker with normal DNS | Would need proxy-aware checking |
| Token counts silently capped at 32,768 | granite `tokenizer.json` ships with truncation at 32,768 and padding on: the BBC page ×20 counted exactly 32,768 tokens until `no_truncation()` (77,960 after) | `HFTokenCounter` calls `no_truncation()` and `no_padding()`; tests check a 45k-token text and batch = single counts | Wrong counts would let chunks overflow the model windows unnoticed |
| Chunks fit the embedder but overflow the reranker | Reranker (XLM-R) ÷ granite tokens on `data/parsed`: 0.83–0.88 Arabic, 1.06 English, 1.28 on the CSS-heavy docs page | Chunk cap 400 granite tokens (target 300); retrieval must set reranker `max_length` ≥ 640 | 450 granite tokens could be ~576 reranker tokens before the query is added |
| Slide-style PDFs give dozens of tiny sections | VP candidacy PDF: 44 sections, most under 60 chars (`## 01`, `## 07`) | Runs of small sections under one parent merge (headings kept inline) up to the target; never across a higher heading. 40 sections → 10 chunks | 5-character chunks carry no answer and pollute the top-k |
| Heading with no text under it | Same PDF: `## Contents`, `## 07`; docs pages with an H2 directly followed by an H3 | Followed by a descendant: lives on only in the descendants' `heading_path`. Otherwise merged forward; a trailing one joins the previous chunk | A chunk that is only a heading is noise |
| Table larger than one chunk | Tests: a 100-row table at a 40-token budget | Split at row boundaries; the header (and `|---|` row) repeated at the top of every piece | Rows without column names are meaningless |
| Unclosed code fence | Tests: `` ``` `` without a closing fence | Block runs to the end of its section (CommonMark behaviour), then splits at lines if too large | Otherwise the rest of the document would be treated as code |
| One "word" larger than the budget | Tests: a 600-character run with no spaces (long URL, base64, unspaced text) | Last-resort cut at a token offset (lossless), logged as `chunk_hard_split` | The token cap must always hold |
| int8 embedder gives different vectors in a batch | granite `model_quint8_avx2.onnx`: a padded batch changed a text's vector by up to 0.012 per component (cosine 0.994 to the same text alone); same-length batches still 0.006 | One sequence per `session.run` (`OnnxDenseEncoder`); test checks alone vs inside a list within 1e-4. Batch 1 was also faster (6.3 vs 5.2 chunks/s) | Activations are quantized per call; queries and documents must get the same vector for the same text |
| fastembed BM25 downloads at runtime | fastembed 0.9.0 `Bm25` resolves the `Qdrant/bm25` repo even with custom stopwords and `disable_stemmer=True` | Stopword files pinned (revision + sha256) and baked into `$MODELS_DIR/bm25`, passed as `specific_model_path` and `cache_dir`; startup fails if missing | The container is offline (`HF_HUB_OFFLINE=1`) |
| Stopwords never match folded text | `Bm25` compares stopwords with the lower-cased token, but our input is `fold_for_search` output: `إلى` arrives as `الي` | The ar+fr+en stopword union (1,028 words) is folded too (945 after folding); test checks `إلى` is dropped | Otherwise every Arabic stopword with a hamza stays in the index |
| Cross-language stopword collisions | One shared stopword set: `an` (English) is also French "year", `son`, `ou` exist in both | **Accepted.** No stemming and one set keep matching language-agnostic (a French query still matches names and numbers in an Arabic chunk) | Per-language stemmers break matching across languages and on mixed documents |
| BM25 length normalization centred on the wrong length | fastembed's default `avg_len` is 256; our chunks average 105 BM25 tokens (70 chunks of `data/parsed`, median 108, max 202) | `INGEST_BM25_AVG_LEN=110` | Every chunk was treated as short, weakening length normalization |
| Crash between writing the points and saving the JSON | The index then holds the new version and `DATA_DIR/documents` the old one | **Accepted.** The next ingest of that document repairs it; a reindex before that would bring back the old version | Rare (process killed in a ~ms window); a two-phase commit is not worth it here |
| Chunks of a crashed ingest without a marker | Points written before the marker (index 0) stay if the process dies; listing and `corpus_version()` ignore them, search does not | **Accepted.** The next ingest of that `doc_id` deletes every other hash; a reindex drops them too | Same rare window; the marker-last order already keeps listings and the cache correct |
| Re-uploading the same file with a new visibility | Same topic + same sha256 but `public` → `members` | `updated`: visibility rewritten on every point and in the stored JSON, no re-embedding | Treating it as `duplicate` would silently keep the old access level |
